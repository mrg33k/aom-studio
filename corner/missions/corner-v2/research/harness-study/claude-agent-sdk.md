# Claude Agent SDK (Python) — structural brief

**Repo / source:** https://github.com/anthropics/claude-agent-sdk-python at 9d398b6 (v0.2.154, bundles CLI 2.1.274) · **Read on:** 2026-09-17 · **Reader:** Claude (corner:corner-v2 R82, SDK-code reader)
**One line:** A thin Python shell that spawns the Claude Code CLI as a subprocess (`--output-format stream-json --input-format stream-json`) and speaks a bidirectional NDJSON control protocol with it; for apps that want Claude Code's agent loop without its terminal.
**Why it is in the study:** the loop, tool execution and permission evaluation all live in the CLI; the SDK shows exactly which knobs an embedding app gets, which events it sees, and how an app-side gate (permission callback, hooks, in-process tools) plugs into the loop without rebuilding it.

Rules for this brief: structure over opinion. Every claim cites a file path (or a docs URL for closed products) and, where it helps, a short excerpt. Say "not found" rather than guess. Six sections, same order in every brief, so PATTERN.md can be built row by row.

## 1. The loop
- Two entry points: `query()` for one-shot (`src/claude_agent_sdk/query.py:11-16`) and `ClaudeSDKClient` for a persistent session (`src/claude_agent_sdk/client.py:26-65`). Both build the same `SubprocessCLITransport` + `Query` pair and always run "streaming mode" internally (`_internal/client.py:138-154`; `client.py:194-208`).
- Startup: `connect()` runs a `claude -v` probe (2 s cap, `_internal/transport/subprocess_cli.py:802-803, 1147-1188`), spawns the CLI with flags from `_build_command()` (`:563-788`), then `Query.initialize()` sends `control_request{subtype:"initialize", hooks, agents, skills}` and waits up to max(`CLAUDE_CODE_STREAM_CLOSE_TIMEOUT`, 60 s) — "MCP servers may take time to start" (`_internal/query.py:235-289`; `client.py:164-169`).
- A user turn is one stdin line: `{"type":"user","message":{"role":"user","content":prompt},"parent_tool_use_id":null,"session_id":"default"}` (`client.py:268-275`).
- Who decides: the CLI. The SDK never picks the next action; it parses stdout frames and answers control requests (`_internal/query.py:314-405`). The tool loop is not in this repo.
- Budgets: `max_turns` → `--max-turns` ("a turn consists of a user message and assistant response", `types.py:2040-2044`; `subprocess_cli.py:603-604`); `max_budget_usd` → `--max-budget-usd`, ending in `subtype == "error_max_budget_usd"` (`examples/max_budget_usd.py:72`); `task_budget` → `--task-budget`, "the model is made aware of its remaining token budget so it can pace tool use" (`types.py:88-97`). Exhaustion arrives as a `result` frame with `is_error` and a subtype such as `error_max_turns` (`_internal/query.py:58-59`); `ResultMessage.terminal_reason` is `"completed" | "max_turns" | "aborted_streaming" | "aborted_tools"` (`types.py:1363-1371`).
- Turn end: a `result` frame. `receive_response()` yields until and including `ResultMessage` (`client.py:574-577`). With `query()`, stdin is closed after the first result that has no in-flight subagent tasks, and only held open at all when hooks, SDK MCP servers or `can_use_tool` need the return channel (`_internal/query.py:825-867`). Process exit ends the stream via an `{"type":"end"}` sentinel (`:471-473`).
- Multi-turn: the client keeps one subprocess; each `client.query()` writes another user line and the CLI holds the conversation (`client.py:254-282`; `examples/streaming_mode.py:74-94`). Mid-session control: `interrupt()`, `set_permission_mode()`, `set_model()`, `stop_task()` are control requests (`_internal/query.py:690-766`). Results of injected turns (task notifications, peers) carry `origin`, so an app can tell its own prompt's result apart (`types.py:1102-1121`).

## 2. Skills and tools
- Base tool set: `tools` → `--tools`; `[]` disables every built-in (`types.py:1965-1974`; `subprocess_cli.py:584-594`). `allowed_tools` is a permission allowlist, "It does not remove tools" (`README.md:59`; `--allowedTools`, `subprocess_cli.py:600-601`). `disallowed_tools` removes tools from context (`types.py:2053-2058`).
- MCP: `mcp_servers` → `--mcp-config '{"mcpServers":{...}}'` with SDK servers' `instance` stripped (`subprocess_cli.py:660-685`). `strict_mcp_config` → `--strict-mcp-config` ignores project `.mcp.json`, user settings and plugin servers (`types.py:2009-2014`).
- In-process tools: `@tool(name, description, input_schema)` returns an `SdkMcpTool` (`__init__.py:251-335`); `create_sdk_mcp_server()` wraps them in a real `mcp.server.Server`, validating arguments with jsonschema and turning unknown tools, bad input and handler exceptions into `isError` results the model can read (`__init__.py:491-619`). At runtime the CLI sends `control_request{subtype:"mcp_message", server_name, message}`; the SDK routes it through `SdkMcpBridge` over mcp's in-memory transport (`_internal/query.py:554-572`; `_internal/sdk_mcp_bridge.py:1-22, 352-377`). Model-side names are `mcp__<server>__<tool>` (`examples/mcp_calculator.py:158-168`).
- Tool result back to the model: done in the CLI; the SDK only observes it as a `UserMessage` containing `ToolResultBlock` (`_internal/message_parser.py:124-131`).
- Skills vs tools: `skills` is "a context filter, not a sandbox"; it adds `Skill(name)` allow rules and defaults `setting_sources` to `["user","project"]` (`types.py:2255-2275`; `subprocess_cli.py:520-561`). `setting_sources` → `--setting-sources=`; `None` = CLI defaults (user, project, local), `[]` = isolation, "Must include 'project' to load CLAUDE.md files" (`types.py:2243-2253`; `subprocess_cli.py:722-723`). Subagents via `agents` go in the initialize request (`_internal/query.py:270-271`; `types.py:107-126`). The `init` system message lists loaded `tools` and `slash_commands` (`examples/tools_option.py:31-33`; `examples/setting_sources.py:39-44`).
- System prompt: `None` sends `--system-prompt ""` (empty, not the Claude Code prompt); preset `claude_code` + `append` → `--append-system-prompt` (`subprocess_cli.py:569-582`). `exclude_dynamic_sections` strips cwd/auto-memory/git status for cross-user cache hits (`types.py:46-57`).

## 3. Memory
- The SDK holds no memory; it points at CLI-side files. CLAUDE.md loads only with `"project"` in `setting_sources` (`types.py:2252`); `AgentDefinition.memory` (`types.py:119`); "auto-memory" is a dynamic prompt section (`types.py:47-49`); `get_context_usage()` reports `memoryFiles` tokens (`client.py:477-511`).
- Sessions: JSONL under `~/.claude/projects/<sanitized-cwd>/` (`_internal/sessions.py:1-5`); `resume`, `continue_conversation`, `fork_session`, `resume_session_at` (`types.py:2026-2038, 2195-2235`). `SessionStore` mirrors transcript lines to external storage and materializes them for resume (`types.py:1608-1660`; `examples/session_stores/`). The system prompt is snapshotted on first request and reused after resume (`README.md:87`).
- Corrections: `rewind_files()` with `enable_file_checkpointing` (`client.py:341-371`). Per-turn injection: `UserPromptSubmit`/`SessionStart` hooks return `additionalContext` (`examples/hooks.py:73-82`). Ledger of what was done: the session JSONL only; nothing else found.

## 4. Order of operations and approvals
- No gather/plan/act sequence in the SDK; ordering is the CLI's. What the SDK exposes is the gate order for one tool call (`types.py:2135-2151`): `permission_mode` (`default | acceptEdits | plan | bypassPermissions | dontAsk | auto`, `types.py:25-27`, meanings at `query.py:54-60`) → allow rules (`allowed_tools`, settings) → `can_use_tool` only when rules say "ask". A `PreToolUse` hook runs before all of that and an allow there skips the callback. `CanUseToolShadowedWarning` fires when `allowed_tools` or `bypassPermissions` make the callback unreachable (`types.py:1826-1915`).
- Permission protocol: setting `can_use_tool` forces `--permission-prompt-tool stdio` (`types.py:1917-1940`; `subprocess_cli.py:624-627`). The CLI writes `control_request{subtype:"can_use_tool", tool_name, input, permission_suggestions, tool_use_id, title, display_name, description}` and blocks (`types.py:2392-2403`); the SDK answers `{behavior:"allow", updatedInput, updatedPermissions}` or `{behavior:"deny", message, interrupt}` (`_internal/query.py:484-536`). `title` is the ready prompt sentence ("Claude wants to read foo.txt"), `display_name` a button label (`types.py:246-253`). `updated_permissions` carries `PermissionUpdate{type: addRules|setMode|..., destination: userSettings|projectSettings|localSettings|session}`, i.e. the "always allow" tier (`types.py:130-161`).
- Hooks as gates: events `PreToolUse, PostToolUse, PostToolUseFailure, UserPromptSubmit, Stop, SubagentStop, PreCompact, Notification, SubagentStart, PermissionRequest` (`types.py:284-295`); registered by callback id in initialize, invoked via `hook_callback` control requests (`_internal/query.py:244-263, 538-552`). Returns: PreToolUse `permissionDecision: allow|deny|ask|defer`, `updatedInput`, `additionalContext` (`types.py:437-444`); PostToolUse `updatedToolOutput`, `additionalContext` (`:447-462`); common `continue_: False` + `stopReason`, `decision:"block"`, `systemMessage`, `reason` (`:541-582`). `defer` stops the run and hands the call back in `ResultMessage.deferred_tool_use` (`types.py:1301-1311`). Matchers on one event run concurrently (`types.py:2159-2163`); per-matcher timeout default 60 s (`:622-623`). `Stop` input carries `stop_hook_active` (`:370-374`).
- Loosen/tighten at runtime: `set_permission_mode()` (`client.py:290-315`), `toggle_mcp_server()` (`:395-419`). Undo: `rewind_files` (env `CLAUDE_CODE_ENABLE_SDK_FILE_CHECKPOINTING`, `subprocess_cli.py:846-848`). "Send" is not special-cased; tools can only advertise `destructiveHint`/`readOnlyHint` (`__init__.py:187-206`).

## 5. Steps and events to the UI
- Wire: one JSON object per stdout line, framed by `_LineFramer` (`subprocess_cli.py:1084-1110`), parsed in `_internal/message_parser.py:50-395` into: `SystemMessage(subtype="init", data{tools, slash_commands})`; `AssistantMessage(content=[TextBlock|ThinkingBlock|ToolUseBlock{id,name,input}|ServerToolUseBlock], model, stop_reason, usage, parent_tool_use_id)` (`:151-220`); `UserMessage(content=[ToolResultBlock{tool_use_id, content, is_error}], tool_use_result)` for each tool result (`:96-145`); `ResultMessage(subtype, duration_ms, duration_api_ms, is_error, num_turns, total_cost_usd, usage, result, structured_output, permission_denials, deferred_tool_use, errors, terminal_reason)` (`:308-337`).
- Partial streaming: `include_partial_messages` → `--include-partial-messages` yields `StreamEvent(event=raw API stream event)` (`:343-354`); the e2e test asserts `message_start` and `content_block_delta` (`e2e-tests/test_include_partial_messages.py:60-62`). Without it, text arrives whole per `AssistantMessage`.
- Steps: subagent/background work arrives as `TaskStartedMessage`, `TaskProgressMessage{usage, last_tool_name}`, `TaskNotificationMessage{status, summary}`, `TaskUpdatedMessage` (`:230-289`; `types.py:1162-1191`); subagent tool frames carry `parent_tool_use_id`, text only with `forward_subagent_text` (`types.py:2183-2193`). `include_hook_events` adds `HookEventMessage(hook_started|hook_response)` (`:73-89`). Unknown frame types are skipped (`:391-395`).
- Stalled/dead: a control request past its timeout raises `Control request timeout: <subtype>` (`_internal/query.py:604-649`); a non-zero CLI exit becomes `ResultError` carrying the CLI's own error text (`:411-453`), re-raised from `receive_messages()` (`:900-912`); `AssistantMessage.error` enumerates `authentication_failed|billing_error|rate_limit|…` (`types.py:1039-1046`). Liveness heartbeat for the main turn: not found.

## 6. Model portability
- No provider layer. `model`/`fallback_model` are strings passed as `--model`/`--fallback-model` (`subprocess_cli.py:615-619`); `set_model()` switches mid-session (`client.py:317-339`); subagents take aliases `sonnet|opus|haiku|inherit` (`types.py:116-117`). `betas`, `thinking`, `effort`, `task_budget` are Anthropic-specific flags (`subprocess_cli.py:612-622, 750-771`). The only abstraction is `Transport` (connect/write/read_messages/close/end_input), meant for remote Claude Code, not other vendors (`_internal/transport/__init__.py:8-84`). Per-model quirk: thinking text omitted by default on Opus 4.7+ (`types.py:1803-1805`).

- Unit tests on three OSes plus an mcp 1.x floor job (`.github/workflows/test.yml:1-60`); live-API e2e tests for hooks, permissions, SDK MCP tools, partial messages, resume (`e2e-tests/README.md:45-51`, "less than $0.10"). Telemetry per turn: cost, usage, duration, `num_turns`, `model_usage` on `ResultMessage` (`types.py:1340-1357`); `get_context_usage()` (`client.py:477-511`); OTEL trace context propagated into the CLI (`subprocess_cli.py:820-844`). ## 8. The feel: what the harness does so a normal model feels smarter than it is
- Anticipating the next step: `ToolPermissionContext.suggestions` — the CLI proposes the rule that would make this approval permanent, and `PermissionResultAllow.updated_permissions` lets the app persist it (`types.py:227-229, 259-264`). `task_budget` lets the model pace itself (`types.py:88-97`).
- Recalling unasked: `UserPromptSubmit`/`SessionStart` hooks inject `additionalContext` every turn (`examples/hooks.py:73-82`); CLAUDE.md via `setting_sources` (`types.py:2252`); `resume`/`continue_conversation` (`types.py:2026-2031`).
- Showing work: `StreamEvent` deltas, `ToolUseBlock` → `ToolResultBlock` pairs, `TaskProgressMessage.last_tool_name` (`types.py:1212-1226`), `HookEventMessage`.
- Never dead-ending: a deny returns `message` to the model, not silence (`_internal/query.py:529-532`); tool failures come back as `isError` results, never protocol errors (`__init__.py:594-615`); `defer` parks the call in `deferred_tool_use` for later resume (`types.py:1301-1311`); `fallback_model` (`types.py:2066`); `ResultError` carries the CLI's own explanation (`_internal/query.py:411-434`).
- One good question: the permission request arrives with `title`, `display_name`, `description` ready for a one-tap prompt (`types.py:246-253`); a hook's `permissionDecision:"ask"` reason is forwarded as `decision_reason` (`:242-245`).
- Continuity: session JSONL, `SessionStore` mirror, `resume_session_at` forks (`types.py:2199-2235`), system-prompt `snapshot` (`types.py:58-69`).

## 9. The one thing to copy outright
**Copy:** the permission gate as a typed request/response over the loop's own channel — `can_use_tool(tool_name, input, context{title, display_name, suggestions, tool_use_id})` → `PermissionResultAllow(updated_input, updated_permissions)` | `PermissionResultDeny(message, interrupt)` (`_internal/query.py:484-536`; `types.py:221-273`; `examples/tool_permission_callback.py:26-93`). It is Corner's send/approve tier exactly: the model proposes, the phone shows `title`, one tap allows, denies, or allows-always; the model receives the denial reason and continues.

**Avoid:** leaving `setting_sources` at `None`. It loads user + project + local settings, and without `strict_mcp_config` also every `.mcp.json` server, hook, plugin and skill the CLI can find (`types.py:2243-2253, 2009-2014`); `initialize` then waits on all of it (`_internal/query.py:283`). Corner needs none of that discovery.

**Lightest scoped loop with only our tools, no project hooks:** `query(prompt, options=ClaudeAgentOptions(system_prompt="…", tools=[], mcp_servers={"corner": create_sdk_mcp_server("corner", tools=[…])}, allowed_tools=["mcp__corner__<name>", …], setting_sources=[], strict_mcp_config=True, max_turns=N))`. `tools=[]` drops built-ins (`types.py:1969`), `setting_sources=[]` is "SDK isolation mode" (`types.py:2250-2251`), `strict_mcp_config` blocks external servers (`types.py:2009-2014`), and `query()` already runs streaming mode so in-process MCP works without `ClaudeSDKClient` (`_internal/client.py:138-154`), despite `README.md:102` implying otherwise. Set `CLAUDE_AGENT_SDK_SKIP_VERSION_CHECK=1` to skip the extra `claude -v` spawn (`subprocess_cli.py:802`). Wildcard `mcp__corner__*` in `allowed_tools`: not found in SDK code; list names explicitly.

**Does the code explain a 159 s startup with project settings?** Not directly. SDK-side costs are only the `claude -v` probe (2 s cap) and the initialize handshake (60 s cap, `client.py:166-169`), whose comment blames MCP server start-up (`_internal/query.py:283`). Everything project settings pull in — `.mcp.json` servers, hooks, plugins, skills, CLAUDE.md — runs inside the CLI and is invisible here. Because 159 s exceeds the 60 s initialize cap, the observed hang (`corner/missions/corner-v2/GOAL-next-phase.md:16`, a `claude -p` run, not this SDK) most likely sat in the first turn (a `PreToolUse`/`UserPromptSubmit` hook, or a slow MCP server the model waited on), not in the handshake; `get_mcp_status()` (`client.py:444-475`) would show which server was `pending`/`failed`.
