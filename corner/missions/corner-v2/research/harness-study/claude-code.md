## 1. The loop
Documented as three blended phases per turn: "gather context, take action, and verify results", with Claude "chaining dozens of actions together and course-correcting along the way" from tool results (how-claude-code-works). The model decides the next action; the harness executes tools and feeds results back. A turn ends when the model stops calling tools (`end_turn`) or hits `--max-turns` or cost/token limits; on exhaustion the loop halts and reports. Sessions persist as JSONL under `~/.claude/projects/`; `--resume` reopens a session id, `--continue` the latest, `--fork-session` copies history to a new id. What carries between turns inside a session is the transcript itself plus auto memory (section 3).

## 2. Skills and tools
Skills are `SKILL.md` files with YAML frontmatter under `.claude/skills/<name>/` (project), `~/.claude/skills/<name>/` (user) or inside a plugin. They load on demand: "Claude sees skill descriptions at session start, but the full content only loads when a skill is used"; the `description` is what triggers the model to invoke one; `disable-model-invocation: true` reserves a skill for the user (skills). Built-in tools: Read, Write, Edit, Bash, Glob, Grep, WebSearch, WebFetch. MCP servers attach via `--mcp-config` or `.mcp.json`; tool schemas are deferred and fetched on demand via a tool-search step; `--strict-mcp-config` uses only the given config (mcp). Plugins bundle skills, agents, hooks and MCP servers behind a `.claude-plugin/plugin.json` manifest; skills inside are namespaced `plugin:skill` (plugins). Subagents live in `.claude/agents/` with their own context, tool set and model. A tool result returns as a `tool_result` block bound to the `tool_use_id`, and the model continues (tool-use overview). The distinction that matters for Corner: skills are procedures the model reads when relevant; tools are calls the harness executes.

## 3. Memory
`CLAUDE.md` files are discovered up the directory tree and concatenated at session start; `@path` imports load at launch (memory). `--setting-sources` picks which scopes load (`user`, `project`, `local`), which is the knob Corner's bridge uses to skip the repo. Auto memory: the model writes notes to `~/.claude/projects/<project>/memory/MEMORY.md`, the first 200 lines or 25 KB load each session, typed as user / feedback / project / reference, and "Claude skips anything it can derive from the codebase" (memory). What persists across sessions: CLAUDE.md, the auto-memory index, transcripts (per `cleanupPeriodDays`). Corrections land as memory notes the model itself writes. No journal or ledger concept.

## 4. Order of operations and approvals
Permission modes: `auto` (a background classifier reviews each action), `default`/manual (asks), `acceptEdits` (edits and safe commands without asking), `plan` (explore only), `dontAsk`, `bypassPermissions`; cycled with Shift+Tab (permission-modes). Rules in `.claude/settings.json` under `permissions` as `allow`, `deny` and `ask` lists of tool patterns, e.g. allow `npm test`, deny `rm -rf /`, ask `curl`. Hooks run shell commands or small models at lifecycle events (PreToolUse, PostToolUse, Stop and others); a PreToolUse hook gates a call deterministically, exit 0 allows and non-zero blocks, independent of what the model wanted (hooks-guide). Destructive or external actions prompt in manual mode unless pre-approved; in `auto` mode the classifier decides. The user loosens or tightens with the mode, the three lists, and hooks. This is the structure Patrik described wanting instead of "never send": a tier per action, remembered, adjustable.

## 5. Steps and events to the UI
`--output-format stream-json` emits one JSON object per line: a `system` init line (session id, tools, model), `assistant` lines whose content holds text and `tool_use` blocks, `user` lines whose content holds `tool_result` blocks, and a final `result` line with the outcome and usage. With `--include-partial-messages` the raw streaming deltas arrive wrapped as `{"type":"stream_event","event":{…}}`, where the inner event is the API's `content_block_delta` shape; Corner's bridge parser expects the bare delta and needs the wrapper handled (planner verification against `scripts/v2-team-bridge.py:6513`). `--verbose` adds debug lines. Rendering is the client's job: every `tool_use` is a step, every `tool_result` closes it, text streams from the deltas. A stalled run is not surfaced by the CLI beyond `--max-turns` and the result line; the client owns the clock. Not fetched by the reader: the docs page for this format; treat the shapes above as verified by use, not by citation.

## 6. Model portability
`--model` accepts aliases (`default`, `best`, `fable`, `opus`, `sonnet`, `haiku`, `opusplan`, `[1m]` variants) and resolves in order: `/model` → `--model` → `ANTHROPIC_MODEL` → settings → `ANTHROPIC_DEFAULT_MODEL` → account default. `--fallback-model sonnet,haiku` retries down a chain when the primary fails (model-config). Identical across models: the loop, tool schemas, permission model, hooks, CLAUDE.md loading, auto memory. Per-model: reasoning and speed only. Provider: direct Anthropic API by default; Bedrock, Vertex and Foundry by environment variables and model ids; the CLI does not abstract non-Anthropic models. For Corner that means Claude Code is one lane's loop, not the cross-model loop.

## 7. How they know it is good
`claude plugin eval` runs each case (prompt plus graders) in a fresh isolated session with only the plugin under test, several times, and scores it; graders include `regex`, `tool_used`, `tool_order`, `file_exists`, `llm` (a judge model voting two of three) and `baseline`; results land in `aggregate-result.json`, exit 0 when all cases meet the threshold (plugin-evals). `/skill-doctor` reports per-skill usage and context cost over seven days. The `tool_used` and `tool_order` graders are exactly the "hands station" the Corner gauntlet lacks.

## 8. The feel: what the harness does so a normal model feels smarter than it is
- Auto-loaded context in a fixed order: system prompt, auto memory, environment (cwd, platform, git state), MCP tool names with deferred schemas, CLAUDE.md files, skill descriptions (context-window). The model starts every turn oriented without being told to orient.
- Skills by description: procedures the model picks up when the ask matches, loaded only then, so 300 skills cost nothing until one is needed.
- Deferred tool schemas plus tool search: many tools, small context.
- Subagents for parallel or high-volume work with isolated context.
- Hooks that verify after every edit without the model deciding to (PostToolUse lint or test): deterministic follow-through.
- Dynamic context injection in skills (`!`command``) so the model sees live state, not stale notes.
- Auto memory the model writes for itself, typed, and reads first next session.

## 9. The one thing to copy outright
Copy: the permission structure, three lists (`allow`, `deny`, `ask`) plus modes plus a PreToolUse gate, with the user able to move any action between tiers. It is an order of operations for approvals, not a rule, and it is what Patrik asked for by name. Avoid: loading a whole repo's hooks, plugins and skills into a chat turn; Corner measured 159 s against 8 s, the docs describe every `.claude/` directory up the tree being parsed at startup, and the documented light path is `--setting-sources user` from a neutral cwd plus `--mcp-config` (with `--strict-mcp-config`) carrying only the servers the turn needs, or the Agent SDK, which loads only what is registered programmatically.
