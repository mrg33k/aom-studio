# OpenHands — structural brief

**Repo / source:** https://github.com/OpenHands/software-agent-sdk @ 7ae26cc (2026-09-16), read because the OpenHands/OpenHands clone (@ a040303) is now only the "Agent Canvas" frontend — its `AGENTS.md` says agents, tools, events and the server API live in `software-agent-sdk`. Paths below are prefixed `sdk:` (software-agent-sdk) and `canvas:` (OpenHands/OpenHands). · **Read on:** 2026-09-17 · **Reader:** Claude (corner:corner-v2 R82)
**One line:** A Python SDK + agent-server (REST/WebSocket) that runs a function-calling coding agent over an append-only event log, with a React control center that subscribes to that log.
**Why it is in the study:** The event stream is the product: every step is a typed, persisted event; the UI and the LLM context are both projections of the same log.

Rules for this brief: structure over opinion. Every claim cites a file path (or a docs URL for closed products) and, where it helps, a short excerpt. Say "not found" rather than guess. Six sections, same order in every brief, so PATTERN.md can be built row by row.

## 1. The loop
- **Status machine** `ConversationExecutionStatus`: IDLE, RUNNING, PAUSED, WAITING_FOR_CONFIRMATION, FINISHED, ERROR, STUCK, DELETING; terminal = FINISHED/ERROR/STUCK (`sdk:openhands-sdk/openhands/sdk/conversation/state.py:48-79`).
- **Turn start:** `send_message()` appends a user `MessageEvent`; a message on FINISHED/STUCK resets to IDLE; keyword skills are matched here (`sdk:.../conversation/impl/local_conversation.py:1825-1888`).
- **Run loop** (`local_conversation.py:1920-2066`), each iteration under the state lock: break on PAUSED/STUCK; on FINISHED run Stop hooks (which may refuse and inject feedback, 1960-1988) then break; `_check_stuck_or_nudge()`; clear WAITING_FOR_CONFIRMATION; `agent.step()`; break if the step set WAITING_FOR_CONFIRMATION; budget check → `MaxBudgetReached`; `iteration >= max_iteration_per_run` (default 500, line 219) → ERROR + `ConversationErrorEvent(code="MaxIterationsReached")` (2037-2058). Any exception → ERROR (2059-2066).
- **Who decides:** the model, via tool calls. `Agent._step()` (`sdk:.../agent/agent.py:645-760`): execute still-unmatched actions first (653-660), build messages from `state.view` through the condenser (688-697), `llm.generate(tools=..., add_security_risk_prediction=True)` (724-731), tool calls → `ActionEvent`s → executed → `ObservationEvent`s (1384-1446).
- **Turn end:** the model calls `finish` (`sdk:.../tool/builtins/finish.py:21-22`); calls after it in the same response are discarded (`agent.py:201-226`); `finalize()` marks FINISHED unless a critic asks for another pass (340-371).
- **Stuck detection** (`sdk:.../conversation/stuck_detector.py`): scans the last 20 events since the last user message (22, 67-82) for identical action+observation, identical action+error, agent monologue, alternating A/B, context-window loop (stub, 322-331). Before STUCK, one nudge: when an action-error streak hits the threshold it injects an environment message "You've called `X` with the same arguments N times… try a different approach", once per streak (243-275; `local_conversation.py:736-760`).
- **Pause vs interrupt:** `pause()` lands between steps and emits `PauseEvent`; `interrupt()` cancels the in-flight asyncio task → PAUSED + `InterruptEvent` (2697-2757).
- **Multi-turn:** one log per conversation. The loop deliberately does not break on FINISHED so a message sent while finishing is not lost (2016-2029).

## 2. Skills and tools
- **Tools** are `ToolDefinition[ActionT, ObservationT]` pydantic classes with an executor and MCP-style `ToolAnnotations` (`readOnlyHint`, `destructiveHint`, `idempotentHint`) (`sdk:.../tool/tool.py:215-247, 347-420`), registered by name (`sdk:.../tool/registry.py:113-200`). MCP servers are wrapped per tool by `MCPToolDefinition` (`sdk:.../mcp/tool.py:242-360`). Builtins: finish, think, invoke_skill, switch_llm, vision_inspect (`sdk:.../tool/builtins/`); bundled: terminal, file_editor, grep, glob, task_tracker, browser_use, delegate (`sdk:openhands-tools/openhands/tools/`).
- **Two meta-fields injected into every non-read-only tool schema:** `security_risk` (enum the model fills) and `summary` ("approximately 10 words describing what this specific action does") (`tool.py:697-717, 900-945`); the agent pops them from the args (`agent.py:1088-1135`).
- **Skills = procedures, not calls.** `Skill` loads from SKILL.md frontmatter (AgentSkills) or legacy markdown; sources: explicit list, `~/.openhands/skills`, the public extensions repo, project `.openhands/skills`, AGENTS.md/CLAUDE.md/.cursorrules (`sdk:.../skills/skill.py:355-480`; `sdk:.../skills/utils.py:312-346`; `sdk:.../context/agent_context.py:78-140`). Triggers: `KeywordTrigger`, `TaskTrigger`, `PathTrigger` (`sdk:.../skills/trigger.py`).
- **Loading tiers** (`agent_context.py:327-390`): no trigger → full body always in `<REPO_CONTEXT>`; triggered or AgentSkills-format → only name+description (≤1024 chars) in `<available_skills>`, body read on demand. **Keyword trigger:** on each `send_message`, whole-token match against the user text appends the skill body as `extended_content` of the user MessageEvent, skipping skills already activated in this conversation (`agent_context.py:509-566`; `skill.py:164-176, 732-754`; `local_conversation.py:1858-1888`). **Path trigger** fires when a tool touches a matching file (`agent_context.py:568-600`).
- **Result back to the model:** `ObservationEvent.to_llm_message()` → `tool` role with `tool_call_id`; tool exceptions become `AgentErrorEvent`, also an observation, so the model self-corrects (`sdk:.../event/llm_convertible/observation.py:32-71, 138-185`; `agent.py:1429-1446`).

## 3. Memory
- **The log is the memory.** `EventLog` is file-backed, one file per event, plus `base_state.json` autosaved on every field change, coalesced per lock block (`sdk:.../conversation/event_store.py:34-60`; `state.py:430-460, 596-625`). Reconnecting clients replay with `resend_mode=all|since` (`sdk:openhands-agent-server/openhands/agent_server/sockets.py:227-345`).
- **Model context = `View.from_events(log)`.** `Condensation` events are replayed onto the view: drop `forgotten_event_ids`, insert a `CondensationSummaryEvent` (user role) at `summary_offset`. The log itself is never rewritten (`sdk:.../context/view/view.py:32, 118-143`; `sdk:.../event/condenser.py:12-107`).
- **Condenser** `LLMSummarizingCondenser` (rolling): triggers on >`max_size` events (240), tokens > min(condenser cap, LLM effective input limit), or an explicit `CondensationRequest`; tokens/request are HARD, event count SOFT (`sdk:.../context/condenser/llm_summarizing_condenser.py:48-58, 99-187`). Keeps `keep_first` (2), forgets down to half, summarizes with a fixed schema USER_CONTEXT / TASK_TRACKING / COMPLETED / PENDING / CURRENT_STATE (`.../condenser/prompts/summarizing_prompt.j2`). Provider context-overflow → `CondensationRequest` → retry (`agent.py:769-810`); HARD with nothing to forget → `hard_context_reset` (`.../condenser/base.py:141-190`). User can force it: `POST /{id}/condense`.
- **Across sessions:** two-tier `MEMORY.md` (user `~/.openhands/memory/`, project `.openhands/memory/`) injected into `<MEMORY_CONTEXT>` under a 6000-char budget, truncated from the top; daily logs read on demand (`sdk:.../context/memory.py:1-80`; `sdk:.../context/prompts/sections/dynamic.py:75-96`). The prompt tells the agent to append near the end of a task and to record "what was expensive to learn: root causes, environment quirks, user preferences, decisions and their reasons", never secrets (`.../sections/static.py:102-165`). **Corrections land only if the agent writes them** — not found: automatic capture of user corrections.

## 4. Order of operations and approvals
- **No planner.** Order is prompt-guided: `<PROBLEM_SOLVING_WORKFLOW>` EXPLORATION → ANALYSIS → TESTING → IMPLEMENTATION → VERIFICATION (`static.py:233-253`); a read-only PLANNING preset exists (`sdk:.../context/prompts/presets.py:52-105`).
- **Approval = policy × risk.** `state.confirmation_policy` defaults to `NeverConfirm`; alternatives `AlwaysConfirm`, `ConfirmRisky(threshold=HIGH, confirm_unknown=True)` (`sdk:.../security/confirmation_policy.py`; `state.py:123`). Risk LOW/MEDIUM/HIGH/UNKNOWN (`sdk:.../security/risk.py`). `LLMSecurityAnalyzer` simply returns the model's own `security_risk` claim (`sdk:.../security/llm_analyzer.py:19-29`); read-only tools skip risk; no analyzer → UNKNOWN (`agent.py:1088-1112`). ToolShield analyzers exist (`sdk:.../security/toolshield_*.py`, not read).
- **Gate:** after the model proposes actions, `_requires_user_confirmation`: a lone `finish`/`think` never asks; otherwise any risk the policy flags → status WAITING_FOR_CONFIRMATION, loop exits, the `ActionEvent`s sit in the log unexecuted (`agent.py:1047-1086`). **Accept = call `run()` again**; `_step` executes unmatched actions first (`agent.py:653-660`; `sdk:.../agent_server/event_service.py:1654-1667`). **Reject** writes a `UserRejectObservation` per action, status → IDLE (`local_conversation.py:2627-2660`). Toggled live via `POST /{id}/confirmation_policy` and `/security_analyzer` (`sdk:.../agent_server/conversation_router.py`); UI shows a lock icon when `confirmation_mode` is on (`canvas:src/components/features/chat/confirmation-mode-enabled.tsx`).
- **Hooks:** PreToolUse / PostToolUse / UserPromptSubmit / SessionStart / Stop, matcher + shell command, can block (`sdk:.../hooks/types.py:9-35`; `sdk:.../hooks/config.py:40-134`); a blocked user message ends the turn (`agent.py:664-670`).
- **Undo:** events carry `parent_id`, with `fork` and `navigate` endpoints over the tree (`sdk:.../event/base.py:33-40`; `conversation_router.py`); per-conversation git worktrees (`sdk:AGENTS.md`). Not found: per-action undo.

## 5. Steps and events to the UI
- **Wire shape:** every `Event` is a frozen pydantic discriminated union with `id`, `timestamp`, `source` (user/agent/environment), `parent_id` (`sdk:.../event/base.py:20-40`). Kinds: SystemPrompt, Message, Action (thought, reasoning, tool_call, security_risk, summary), Observation, AgentError, UserRejectObservation, Condensation*, Pause, Interrupt, ConversationError (never sent to the LLM; carries a `classification` for the UI), ConversationStateUpdate, StreamingDelta, HookExecution, Token (`sdk:.../event/__init__.py:1-57`; `.../event/conversation_error.py:11-35`).
- **Transport:** `EventService` persists then publishes to a `PubSub[Event]`; the `/events/{id}` websocket subscribes, receives a `full_state` `ConversationStateUpdateEvent` first, then optional replay, then live (`event_service.py:138-145, 825-857`; `sockets.py:227-345, 540-550`). Status and token stats are pushed as `ConversationStateUpdateEvent(key="execution_status"|"stats")`, so the UI never polls (`sdk:.../event/conversation_state.py:18-104`; `event_service.py:951-983`).
- **Text streaming:** `StreamingDeltaEvent` goes to PubSub only, never to disk; the event id is minted before streaming so the client retires the live slot when the durable `MessageEvent` arrives (`sdk:.../event/streaming_delta.py`; `sdk:.../agent/stream_context.py:1-60`).
- **UI:** `useAgentState` maps status → AgentState; STUCK → ERROR "for now" (`canvas:src/hooks/use-agent-state.ts:12-35`); status text: STUCK falls through to the generic agent-error string (`canvas:src/utils/status.ts:101-121`); `agent-status.tsx` shows spinner/stop/resume and flashes the tab (`canvas:src/components/features/controls/agent-status.tsx:38-90`). MaxIterations arrives as a `ConversationErrorEvent` banner (`canvas:src/components/features/chat/error-message-banner.tsx:19-105`). Runs of ≥2 action/observation cards fold into an `EventGroup` titled by the latest action's `summary` plus "{n} actions completed" (`canvas:src/components/conversation-events/chat/group-events.ts:12-50`; `.../event-message-components/event-group.tsx:17-57`). Confirm/Reject render inline with a `RiskAlert` and POST `/respond_to_confirmation` (`canvas:src/components/shared/buttons/conversation-confirmation-buttons.tsx:1-55`). Sent messages show optimistically until the server echoes them (`canvas:src/components/features/chat/pending-user-messages.tsx:13-25`).

## 6. Model portability
`LLM` wraps litellm `completion`/`responses` with tenacity retries and a `FallbackStrategy` to alternate LLMs (`sdk:.../llm/llm.py:221-260, 349-351, 612-617, 957-1010, 1565, 1790`). Per-model quirks live in one registry, `ModelFeatures` (reasoning effort, thinking mode, prompt cache, stop words, responses API, vision, inline images) resolved by substring rules plus litellm metadata; policy: never in `llm.py` (`sdk:.../llm/utils/model_features.py:48-140`; `sdk:AGENTS.md`). Models without native function calling get prompt-mocked tool calls with in-context examples (`sdk:.../llm/mixins/non_native_fc.py:26-60`). The effective input limit from litellm drives condensation (`llm.py:2452-2458`). Identical across models: log, tools, prompt sections, loop. Switching: `switch_llm` builtin tool and `POST /{id}/switch_llm|switch_profile`.

## 7. How they know it is good
SWE-bench variants, GAIA, terminalbench etc. dispatched through a `run-eval.yml` workflow and monitored in Datadog (`sdk:.agents/skills/run-eval.md:1-45`; `sdk:.github/run-eval/`). Integration tests `t*.py` (required, task completion) vs behavior tests `b*.py` (optional, "doesn't implement when asked for advice", LLM judges) (`sdk:tests/integration/BEHAVIOR_TESTS.md:1-50`). A `CriticBase` with `IterativeRefinementConfig` re-runs a task when the score is under threshold (`sdk:.../critic/base.py:20-60`). Frontend: PostHog, one canonical event per milestone (`canvas:AGENTS.md`, "Tracking / Analytics Architecture").

## 8. The feel: what the harness does so a normal model feels smarter than it is
- **Showing the work:** the forced `summary` field gives every step a 10-word human caption without reading arguments (`tool.py:900-945`); `thought`/reasoning ride on the `ActionEvent` (`.../llm_convertible/action.py:24-70`); grouped cards keep the scroll short (`group-events.ts`).
- **Never dead-ending:** tool exceptions → `AgentErrorEvent` the model reads (`agent.py:1429-1446`); malformed tool call → the error as a user message (736-746); content-filter block → "please continue, rephrasing" (748-767); context overflow → condense and retry (769-810); repeated same error → one nudge before STUCK (`stuck_detector.py:243-275`); image sent to a non-vision model → expose a `vision_inspect` tool instead of failing (698-720).
- **Recalling unasked:** keyword skills appended to the user message (`agent_context.py:509-566`); path rules when a file is touched (568-600); MEMORY.md at session start (`memory.py`).
- **Anticipating the next step:** critic follow-up prompts after `finish` (`agent.py:344-371`); Stop hooks that refuse a premature finish (`local_conversation.py:1960-1988`); auto-title from the first message (`sdk:.../conversation/title_utils.py:78-135`).
- **Asking one good question:** not found as a structure; the prompt only says "consult with the user" (`static.py:240-249`). The structural "ask" is confirmation mode: the exact pending action, its risk, one tap, in place.
- **Continuity:** every event on disk; replay on reconnect; a message sent mid-run is queued, not lost (`local_conversation.py:2016-2029`); a resume transcript rebuilds lost ACP sessions (`sdk:.../event/resume_transcript.py:1-48`).

## 9. The one thing to copy outright
**Copy:** the append-only event log as the single source of truth, with `ConversationExecutionStatus` and `ConversationStateUpdateEvent` pushed on the same stream (`state.py:48-79`; `.../event/conversation_state.py:18-104`; `event_service.py:825-857`). For Corner: one per-room event table (user message, action with `summary` + risk, observation, error, condensation, state update); chat, the files rail and the amber needs-you badge become projections; WAITING_FOR_CONFIRMATION is a status, not a modal, and accept is simply "run again".
**Avoid:** letting the model grade its own risk as the gate (`LLMSecurityAnalyzer`, `llm_analyzer.py:19-29`, default policy `NeverConfirm`, `state.py:123`). For an owner's send/pay/delete actions the tier must come from the tool's declared `destructiveHint` (`tool.py:236-247`) or an allowlist, never from the model's self-report; and a 500-iteration default budget (`local_conversation.py:219`) is a desktop assumption, not a phone one.
