# OpenClaw — structural brief

**Repo / source:** https://github.com/openclaw/openclaw at 120ad02b (v2026.9.4, shallow clone) · **Read on:** 2026-09-17 · **Reader:** Claude (corner:corner-v2 R82 harness study)
**One line:** An open-source personal agent daemon ("Gateway") on the owner's own machine that answers in the chat apps they already use (Telegram, WhatsApp, Slack, iMessage, 20+), with any model, file-based skills, file+SQLite memory, a cron scheduler and owner-set rules.
**Why it is in the study:** The closest existing thing to Corner: one assistant reached over chat, working while the owner is away from a keyboard. Approval-in-chat, progress-in-chat and proactive scheduling are solved structurally, and its skills catalog is a drop-in replacement for a regex router.

Rules for this brief: structure over opinion. Every claim cites a file path (or a docs URL for closed products) and, where it helps, a short excerpt. Say "not found" rather than guess. Six sections, same order in every brief, so PATTERN.md can be built row by row.

## 1. The loop

**Message → turn.** A channel message enters `dispatchReplyFromConfig` (`src/auto-reply/reply/dispatch-from-config.ts:28`): gather → prepare context → choose route → execute → finalize (imports, lines 7–16). Slash commands and directives (`/model`, `/queue`, `/approve`, `/elevated`) are handled before any model call (`src/auto-reply/reply/commands-*.ts`). Runs serialize per session lane, then a global lane (`docs/concepts/queue.md`). A message arriving mid-run is *steered* into the active run by default (500 ms debounce, cap 20); other modes `followup | collect | interrupt` (`get-reply-run-queue.ts:16–48`).

**Who decides.** The model. Core loop `packages/agent-core/src/agent-loop.ts:310–445`: outer `while (true)` for queued follow-ups, inner `while (hasMoreToolCalls || pendingMessages.length > 0)`; tool calls execute as a batch, results are pushed (427–430), `hasMoreToolCalls` recomputed from `stopReason === "toolUse"` / `endTurn === false` (416–421), steering messages injected between batches (422). No planner or router; an **Execution Bias** prompt section stands in (`src/agents/system-prompt.ts:508–516`: "Actionable request: act now … Continue to done/real blocker; no plan-only finish … Final claim needs evidence or named blocker.").

**Budgets.** Time, not steps: 48 h default run timeout (`src/agents/timeout.ts:13`); model idle 120 s cloud / 300 s self-hosted / 60 s under cron (`embedded-agent-runner/run/llm-idle-timeout.ts:28–34`). No max-steps counter found; a `MAX_RUN_LOOP_ITERATIONS` backstop is referenced (`run/idle-timeout-breaker.ts:5`) but its definition was not located. Bolted-on guards: idle breaker trips after 5 idle timeouts with no output (`idle-timeout-breaker.ts:15`, comment cites "761–1384 paid Anthropic calls in 60 seconds"); tool-loop detection warns at 10, critical 20, circuit breaker 30 over a 30-call window (`src/agents/tool-loop-detection.ts:51–54`). Approval waits pause the budget (`agent-run-approval-wait.ts:44–60`); `ask_user` does not (`docs/concepts/agent-loop.md` "Timeouts").

**Ending.** `stopReason: "stop"` with no tool calls; `NO_REPLY` is filtered. A required-reply turn ending after tools with no answer gets a tool-free finalization pass; a run ending on a tool failure gets a fallback warning so silence never reaches the user (`agent-loop.md` "Reply shaping"; `run/tool-error-warning.ts:20–50`).

**Across turns.** SQLite transcript per agent. Near the limit, a *memory flush* turn writes durable facts to `memory/YYYY-MM-DD.md` (`extensions/memory-core/src/flush-plan.ts:13–40`), then compaction summarizes older turns keeping ~20,000 recent tokens (`docs/concepts/compaction.md`). The system prompt has a cache boundary so the stable prefix is reused (`system-prompt.ts:1316`).

## 2. Skills and tools

**Tools** are typed schemas assembled per attempt (`run/attempt-tool-catalog.ts:48`), filtered by an allow/deny policy pipeline (global/agent/channel/sender; `src/skills/runtime/tool-dispatch.ts:1–30`) and by model compatibility (lean sets for local models, schema quarantine; `attempt-tool-catalog.ts:19–27`). Plugins in `extensions/` register tools/providers/channels via `openclaw/plugin-sdk/*` (`extensions/anthropic/index.ts:10–17`); MCP servers attach as bundles (`src/agents/agent-bundle-mcp-*.ts`); big catalogs use deferred schemas plus `tool_search` (`system-prompt.ts:1099`).

**Skills** are `SKILL.md` files (AgentSkills spec): frontmatter `name`, `description`, optional `metadata.openclaw.requires { bins, env, config }`, `os`, `user-invocable`, `disable-model-invocation`, `command-dispatch: tool` (`docs/tools/skills.md` "SKILL.md format", "Gating"; parser `src/skills/loading/frontmatter.ts:28–37`). Discovery walks seven precedence tiers (workspace `skills/` → `.agents/skills` → `~/.agents/skills` → managed → workshop → bundled `skills/*` → plugin/extra dirs), gating each by binary/env/config presence and per-agent allowlist (`docs/tools/skills.md` "Loading order"). `custodian-skills/` ships only to the system agent.

**Loaded into a turn: names, not bodies.** The prompt gets `<available_skills><skill><name/><description/><location/></skill>…` (`src/skills/loading/skill-contract.ts:122`, `workspace-skill-prompt.ts:173–174`), budgeted to 150 skills / 18,000 chars (`skill-prompt-limits.ts:10–11`). The Skills section is seven lines (`src/agents/system-prompt.ts:268–275`): "Scan <available_skills>. Clear match: read exact <location> with `read`; obey. Several: most specific. None: read none. Up-front max one. Never invent paths." **Picking** is the model's; **loading** is a lazy `read` of the SKILL.md. Users can force it with `$skill` references (max 8, `src/skills/discovery/chat-command-invocation.ts:9`) or `/skill` commands; `command-dispatch: tool` skips the model.

**Skill vs tool.** Skills are procedures that teach tool use; tools are calls. The agent cannot write SKILL.md directly — it drafts a *Skill Workshop* proposal for operator review (`docs/tools/skills.md` "Skill Workshop"). Tool results return as `toolResult` messages, size-capped from the context window (`run/attempt-exec-approval-continuation.ts:31`), with a `tool_result_persist` hook before the transcript write.

## 3. Memory

**Tiers** (`docs/concepts/memory-architecture.md` "The tier model"):

| Tier | Surface | Written by | Loaded |
|---|---|---|---|
| Instructions | `AGENTS.md`, `SOUL.md`, `IDENTITY.md` | human | every session |
| Curated core | `MEMORY.md`, `USER.md` | dreaming consolidation, direct request | session start, budgeted |
| Episodic | `memory/YYYY-MM-DD.md`, transcripts | agent, flush, ingestion | never; `memory_search`/`memory_get` |
| Prospective | standing intents (SQLite), cron jobs | `intent` tool, scheduler | only when a trigger fires |
| Review | `DREAMS.md` | dreaming | never |

**Up front.** Bootstrap files `AGENTS.md`, `SOUL.md`, `IDENTITY.md`, `USER.md`, `BOOTSTRAP.md` (new workspace only), `MEMORY.md` (`docs/concepts/system-prompt.md` "Workspace bootstrap injection"; `src/agents/workspace.ts:62–66`), capped 20,000 chars/file, 60,000 total, with a truncation notice. Daily notes are never injected on ordinary turns.

**On demand, zero model calls.** `memory_search` ranks hybrid relevance × 30-day half-life recency × write-time importance (`extensions/memory-core/src/tools.ts:434`). **Trigger injection:** curated lines carry `<!-- trigger: gateway setup, network safety --> <!-- importance: 9 -->`; each inbound message is prefiltered against triggers and entries scoring ≥ 0.72 are injected hidden, at most three, curated tier only (`memory-architecture.md` "Lane 1"; implementation file not located). **Escalation:** a blocking recall sub-agent runs only on recall intent *and* no strong lane-1 hit (`extensions/active-memory/escalation.ts`).

**Writes.** One primary writer: *dreaming*, a cron-scheduled light → REM → deep sweep (`extensions/memory-core/src/dreaming-phases.ts`, `dreaming.ts:137–139`). Deep ranks candidates on recall frequency/diversity/recency, structurally excludes `untrusted` and `system` provenance, then a tool-free consolidation turn rewrites `MEMORY.md` under a hash check with the pre-image stored and a summary in `DREAMS.md` (`docs/concepts/dreaming.md` "Phase model"). Feeds: agent daily notes, the pre-compaction flush (`flush-plan.ts:16–19`: "APPEND … treat MEMORY.md … as read-only"), session-end transcript ingestion. **Provenance** lives in SQLite columns the model cannot write (`owner | agent | untrusted | system`); cron/heartbeat/subagent sessions never yield durable candidates; recalled content is never re-extracted; a network-sourced tool result taints the rest of the turn (`agent-loop.ts:415`).

**Corrections.** "No hidden state": the owner edits the Markdown or asks; `openclaw memory forget` removes entries from chosen sessions; cancelling a standing intent is durable state, never inferred (`docs/concepts/standing-intents.md`). **Ledgers:** transcripts, a metadata-only audit ledger, cron run history, a background-task ledger (`docs/automation/tasks.md`), per-session `progress_card`.

## 4. Order of operations and approvals

**Sequence.** Prompt-set: Execution Bias plus **Promised Work** (`src/agents/promised-work-prompt.ts:3–10`: "Before ending a turn, arrange an available completion or watch path … Proactively return with the result, link, proof, or a concrete blocker … Progress such as `running` is not completion."). Optional plan via `progress_card` (≤ 1 step `in_progress`).

**Tiers** — `tools.exec.mode` (`docs/tools/permission-modes.md`): `deny` · `allowlist` · `ask` (run matches, human on miss) · `auto` (matches run; an LLM reviewer judges misses → `allow` once / `deny` with a reason returned to the agent / `ask` a human; three consecutive denials escalate to a human) · `full`. Session modes `read-only | guarded | workspace | full` set the filesystem boundary and reviewer (`docs/gateway/permission-modes.md`), changeable mid-task; old pending approvals are cancelled, not granted.

**A risky action, in chat.** The exec tool registers a two-phase approval with the gateway and waits (`src/agents/bash-tools.exec-approval-request.ts:155–190`, `exec.approval.request` → `exec.approval.waitDecision`, `expiresAtMs`); the run emits lifecycle `waiting-approval` and its budget pauses. The channel plugin delivers a native card to the origin chat and/or the approver's DM (`src/infra/approval-native-delivery.ts:32–123`, surfaces `origin | approver-dm`); Matrix seeds ✅ / ♾️ / ❌ reactions. Text fallback `/approve <id> allow|always|deny` (`src/auto-reply/reply/commands-approve.ts:18–31`), accepted only from an authorized sender or `operator.approvals` scope (147–176). `allow-always` mints a SQLite allowlist row (`docs/tools/exec-approvals.md`, `"source": "allow-always"`) bound to the binary's real path/hash. A closed turn invalidates its pending approval.

**Sends.** Messaging-tool sends are governed by per-channel/group/sender tool policy and a cancellable `message_sending` hook (`agent-loop.md` hooks table). A "confirm before sending on the owner's behalf" card: not found.

**Questions.** `ask_user`: 1–3 structured questions, choices in `options`, recommended first with "(Recommended)", `timeoutSeconds` default 900 (`src/agents/tools/ask-user-tool-normalization.ts:6`); "never ask whether to proceed or confirm a plan … If the result is no_answer, continue with best judgment" (`src/agents/tool-description-presets.ts:172–182`). A plain-text reply routes to the pending question before queue handling (`agent-runner-question-input.ts:31–60`).

**Loosen/tighten.** `/elevated on|full|off` gated by `tools.elevated.allowFrom` (`docs/tools/elevated.md`); `/exec security=… ask=…` per message can only tighten; and *standing orders* in `AGENTS.md` — prose programs with Authority / Trigger / Approval gate / Escalation that cron jobs reference (`docs/automation/standing-orders.md`). **Undo:** not found for chat actions; compaction "is not rollback"; only `MEMORY.md` rewrites keep a pre-image.

## 5. Steps and events to the UI

**Wire.** Three streams per `runId`: `lifecycle` (`phase: start | finishing | end | error`, plus `waiting-approval` / `approval-resolved` with `approvalId`), `assistant` (deltas), `tool` (`phase: start | update | end`), and `compaction` (`src/agents/embedded-agent-subscribe.handlers.lifecycle.ts:41–58`, `…tools.start.ts:491–503`, `…tools.completion.ts:435–453`). `agent` RPC returns `{ runId, acceptedAt }` at once; `agent.wait` blocks ≤ 30 s and returns `ok | error | timeout` without cancelling.

**Progress in chat.** No token streaming to channels. Per-channel `streaming.mode` is `off | partial | block | progress` (`docs/concepts/progress-drafts.md`). `progress` edits **one** message — status headline, plan steps (✅ / ▸ / ▢), approval requests, optional tool rows (`🛠️ Bash: run tests`) — created 1.5 s after real work starts and replaced by the answer. The compositor keeps the model's own preamble as headline for 20 s (`src/channels/progress-draft-compositor.ts:45,52`); handlers for tool/item/approval/command-output at `progress-draft-events.ts:44–60`. When the model is quiet, a utility model narrates: ≥ 4 events, ≥ 12 s apart, ≤ 280 chars, ≤ 30 per turn (`src/auto-reply/reply/progress-narrator.ts:26–34`). Slow tools emit typed mid-call progress after 5 s. Typing fires on enqueue, refreshes every 6 s (`docs/concepts/typing-indicators.md`). `progress_card` is the durable status beside the session (`src/agents/tools/progress-card-tool.ts:35`).

**Stalls.** A running tool pings activity every 60 s (`run/tool-activity-heartbeat.ts:20–27`); the channel run-state machine republishes `busy` every 60 s (`src/channels/run-state-machine.ts:19`). Diagnostics mark `session.long_running` at 2 min without progress, `session.stalled`, and abort-drain at ≥ 5 min and 3× the warning (`agent-loop.md` "Stuck session diagnostics"; `src/logging/diagnostic-stability.ts:329–330`). Retryable errors get 15 s grace; a definitive timeout finalizes the chat as `error`/`aborted` with the explanation kept — a failed turn, not a success.

## 6. Model portability

**Abstraction.** `src/llm/stream.ts:84–121` exposes `stream | complete | streamSimple | completeSimple(model, context, options)`; a `Model` carries `api`, `provider`, `id` (36–40). Each provider is a plugin in `extensions/<provider>/` (anthropic, openai, google, ollama, openrouter, litellm, vllm, llama-cpp … ~60) whose `openclaw.plugin.json` declares `providers`, a `modelCatalog` (`api`, `contextWindow`, `maxTokens`, `cost`, `thinkingLevelMap`, `compat`), aliases (`"opus": "claude-opus-5"`) and auth choices (`extensions/anthropic/openclaw.plugin.json`). A local Claude CLI login is a backend (`extensions/anthropic/cli-backend.ts`).

**Identical:** the system prompt ("no runtime default prompt", `docs/concepts/system-prompt.md`), tools, loop, memory, channels. **Per model:** a provider may replace exactly three named sections (`interaction_style`, `tool_call_style`, `execution_bias`) and add a stable prefix / dynamic suffix around the cache boundary; per-provider params (`embedded-agent-runner/extra-params.ts`), compat shims (`model.compat.ts`), thinking maps, lean tool sets and schema quarantine (`attempt-tool-catalog.ts:19–27`).

**Switching.** `/model provider/model` in chat writes a strict user override (no fallback); config `agents.defaults.model.primary` + `fallbacks[]`; cron `--model`. Failure: bounded same-model recovery → auth-profile rotation → next fallback model, turn-local (`docs/concepts/model-failover.md`; `run/failover-policy.ts:1–80`). Alternate harnesses plug in via `agentRuntime.id` (`docs/agent-runtime-architecture.md`).

## 7. How they know it is good

A private QA lab runs YAML scenarios (`qa/scenarios/<theme>/*.yaml`, `qa/README.md`) over a synthetic `qa-channel` with a `mock-openai` provider. The **Personal Agent Benchmark Pack** is ten scenarios — reminder round-trip, thread reply, preference recall, no secret leak, tool-safety follow-through, approval-denial stop, honest task status, share-safe diagnostics, *no fake progress*, failure recovery — each bound to a coverage ID in the maturity scorecard (`taxonomy.yaml:24–35`; `docs/concepts/personal-agent-benchmark-pack.md`). Prompt snapshots are drift-checked in CI; live tests sit behind `OPENCLAW_LIVE_TEST=1`; `qa/frontier-harness-plan.md` is a model bake-off. Dogfooding: "We build OpenClaw with OpenClaw on team.openclaw.ai"; no usage telemetry by default (`VISION.md`).

## 8. The feel: what the harness does so a normal model feels smarter than it is

- **Anticipating.** Execution Bias and Promised Work as code-owned prompt sections (`system-prompt.ts:508`, `promised-work-prompt.ts:3–10`); the agent owns an `automations` tool and is told to use cron, not sleep loops, for "check back later" (`docs/concepts/system-prompt.md`); **standing intents** — the `intent` tool stores event-conditioned reminders in SQLite, matched by FTS prefilter each turn with no model call, cooldown 24 h, max 3 fires, 90-day expiry, ≤ 3 injected (`extensions/memory-core/src/standing-intents-tool.ts`, `standing-intents.ts:19`); **heartbeat** every 30 m with a narrow prompt and `NO_REPLY` / `heartbeat_respond notify:true|false` so quiet stays quiet (`src/auto-reply/heartbeat.ts:8–24`); standing orders in `AGENTS.md`.
- **Recalling unasked.** Bootstrap `MEMORY.md`/`USER.md`; trigger injection of ≤ 3 curated entries; deep recall only when the message asks about the past (§3).
- **Showing the work.** The single edited progress message, utility-model narration, `progress_card`, typing on enqueue (§5).
- **Never dead-ending.** Tool-free finalization pass; fallback warning naming partial results ("timed out after Ns; 3 partial results are available", `run/tool-error-warning.ts:26–35`); `ask_user` "no_answer → continue with best judgment"; reviewer `deny` returns a reason so the agent picks a safer route; overflow → compact and retry; model fallback chain; "Weak/empty result: vary query/path/command/source, then conclude".
- **One good question.** `ask_user` contract: one question, options, recommended first, never "shall I proceed" (§4).
- **Continuity.** Per-agent SQLite transcript with `/new`/`/reset` boundaries; memory flush before compaction; dreaming; `SOUL.md` persona and `BOOTSTRAP.md` first-run conversation (`src/agents/bootstrap-prompt.ts`); auth profile pinned per session for warm caches (`docs/concepts/model-failover.md` "Session stickiness").

## 9. The one thing to copy outright

**Copy:** the lazy skills catalog — `SKILL.md` files with `name`/`description` frontmatter, rendered as a budgeted `<available_skills>` list of name + description + location, and a seven-line prompt contract that makes the model pick a skill and `read` it only on a clear match (`src/agents/system-prompt.ts:268–275`, `src/skills/loading/skill-contract.ts:122`, `skill-prompt-limits.ts:10–11`). It replaces Corner's regex router with model-chosen procedures at ≤ 18k chars of catalog, uses a public spec Corner can author today, and gives every procedure a file the owner can read and edit. Runner-up: the two-phase approval with a stable id, native card + `/approve <id> allow|always|deny` fallback, budget pause, allow-always → allowlist (§4).

**Avoid:** a time-only run budget. OpenClaw bounds the loop by a 48-hour wall clock and idle watchdogs with no per-turn step budget (`src/agents/timeout.ts:13`), then had to bolt on an idle-timeout breaker after one heartbeat burned "$20–30 per incident" (`run/idle-timeout-breaker.ts:11–15`) and a three-tier loop detector. Corner should start with a small explicit step/tool budget per turn and a hard "partial result + offer" on exhaustion, and grow it deliberately.
