# Codex CLI — structural brief

**Repo / source:** https://github.com/openai/codex at 16f59db9 (2026-09-17) · **Read on:** 2026-09-17 · **Reader:** Claude subagent (corner:corner-v2 R82)
**One line:** OpenAI's terminal coding agent (Rust, `codex-rs/`): one model in a tool loop with a sandbox, an approval matrix and a JSONL headless mode, for developers running it in a repo.
**Why it is in the study:** its `codex exec --json` item lifecycle is the cleanest "steps to the UI" contract in the study, and its approval tiers are the most explicit.

Rules for this brief: structure over opinion. Every claim cites a file path (or a docs URL for closed products) and, where it helps, a short excerpt. Say "not found" rather than guess. Six sections, same order in every brief, so PATTERN.md can be built row by row.

## 1. The loop
A user turn is a `RegularTask` whose `run` is `loop { run_turn(...) }`, re-entered only while the input queue holds steered input (`codex-rs/core/src/tasks/regular.rs:76-96`). `run_turn` (`codex-rs/core/src/session/turn.rs:163-785`) does, in order: pre-sampling compaction (:183), discover MCP servers the input mentions (:234), inject skills/plugins as user-role fragments (:308, :395-402), record input and run `UserPromptSubmit` hooks (:366), then the inner `loop` (:423): drain pending user input (:427), capture a step context (:459), inject a time reminder (:497), build the request from the whole history (:513-517), `run_sampling_request` (:524). Tool calls execute inside that request as streamed `FunctionCall` items arrive (`:2470`, `:2550-2554`). The model is the only decider: `needs_follow_up` is true iff it emitted tool calls or the user steered (:544, :567); false → `Stop` hooks (:646) → `break`. No planner, no router.

Budgets: no step or iteration cap found (grep `max_turns|max_steps|max_iterations`: not found). Tokens: after every sample `context_window_token_status` (:555-568) and `token_limit_reached` triggers mid-turn `run_auto_compact` then `continue` (:602-642). The limit is the model's `auto_compact_token_limit`, else 90% of `context_window` (`codex-rs/protocol/src/openai_models.rs:456-460`); the hard cap is `effective_context_window_percent` (`codex-rs/core/src/session/context_window.rs:83-84`). Optional session budget: `RolloutBudgetConfig { limit_tokens, reminder_at_remaining_tokens }` (`codex-rs/core/src/config/mod.rs:1258-1263`) injects reminders as user fragments and ends with `SessionBudgetExceeded` (`codex-rs/core/src/session/rollout_budget.rs:8-40`).

Ending: errors emit `EventMsg::Error` then `break` — "let the user continue the conversation" (`turn.rs:776-779`). Interrupt leaves a `<turn_aborted>` fragment: "commands ... may have partially executed" (`codex-rs/core/src/context/turn_aborted.rs:10`). Across turns the full history lives in `ContextManager.items` (`codex-rs/core/src/context_manager/history.rs:76-79`), persisted as `~/.codex/sessions/YYYY/MM/DD/rollout-<ts>-<thread_id>.jsonl` (`codex-rs/rollout/src/rollout_file_name.rs:67`, `codex-rs/rollout/src/recorder.rs:1705`), resumed with `codex exec resume --last` / `fork` (`codex-rs/exec/src/cli.rs:150-158`).

## 2. Skills and tools
Tools are `ToolSpec::Function(ResponsesApiTool { name, description, parameters: JsonSchema, strict, output_schema })` (`codex-rs/core/src/tools/handlers/plan_spec.rs:42-57`); each handler implements `ToolExecutor { tool_name, spec, handle }` (`codex-rs/core/src/tools/handlers/request_user_input.rs:30-45`). The set is rebuilt per step in `codex-rs/core/src/tools/spec_plan.rs`, gated by `Feature::*` flags (:1042-1231): shell, apply_patch, update_plan, request_user_input, request_permissions, web_search, tool_search, get_context_remaining, new_context, send_message_to_user_async, spawn_agent (`codex-rs/core/src/tools/handlers/`). MCP tools are namespaced and can be `defer_loading` behind `tool_search`; servers a turn needs are inferred from the input (`turn.rs:234-255`). Results return as `FunctionCallOutput` items, truncated by the model's `truncation_policy` (`openai_models.rs:448`).

Skills are `SKILL.md` files with frontmatter (`codex-rs/skills/src/parser.rs:22-43`): `name, description, interface, dependencies.tools (MCP), policy.allow_implicit_invocation` (`codex-rs/skills/src/model.rs:8-20`), scoped User/Repo/System/Admin (`codex-rs/core/src/skills.rs:142-145`); bundled ones install to `$CODEX_HOME/skills/.system` (`codex-rs/skills/src/lib.rs:55-77`). Per turn, `$mentions` are collected, the SKILL.md bodies loaded and injected as text before sampling (`turn.rs:1027-1061`); a skill's MCP dependencies can prompt an install (:1029-1036). So: skills = procedures as text, tools = calls.

## 3. Memory
AGENTS.md: walk up to the `.git` marker, concatenate every AGENTS.md from root to cwd, 32 KiB cap, `AGENTS.override.md` wins, skipped for untrusted projects (`codex-rs/core/src/agents_md.rs:1-18, :43-49, :64`; `codex-rs/core/src/config/mod.rs:250`). Memories (`codex-rs/memories/README.md`): at session start, in the background, Phase 1 extracts `raw_memory` + `rollout_summary` per recent rollout into the SQLite state DB; Phase 2 consolidates into `~/.codex/memories/raw_memories.md` and `rollout_summaries/` via a sub-agent "with no approvals, no network, and local write access only". The read path injects them as a developer message capped at 8,900 bytes (`codex-rs/core/src/context/memory.rs:8-42`). Approvals cache per session (`codex-rs/core/src/tools/approvals.rs:698-703`); `.rules` amendments across sessions (`codex-rs/protocol/src/protocol.rs:4149`). Ledger of what was done: the rollout JSONL. Correction capture beyond memories: not found.

## 4. Order of operations and approvals
Per step: hooks → compaction check → world-state diff → sample → for each tool call `ToolOrchestrator::run` (`codex-rs/core/src/tools/orchestrator.rs:122-235`): "1) Approval" resolves `Skip | NeedsApproval | Forbidden` (`codex-rs/core/src/tools/sandboxing.rs:153-169`); "2) First attempt under the selected sandbox" (:237); on sandbox denial, if `escalate_on_failure`, a `retry_reason` is built (:407-415), the user is asked with that reason (:422-448), then it retries unsandboxed (:450-470). Approval precedence: `PermissionRequest` hooks → Guardian (an automatic reviewer model) → user (`approvals.rs:496-516, :545-561`).

Tiers (`protocol.rs:986-1026`): `untrusted` (ask unless an execpolicy rule allows), `on-request` (default; alias `on-failure`; ask only when the FS sandbox is restricted, table at `sandboxing.rs:195-231`), `granular { sandbox_approval, rules, skill_approval, request_permissions, mcp_elicitations }`, `never` (failures go back to the model). Sandbox (`protocol.rs:1072-1120`): `read-only`, `workspace-write` (+`writable_roots`, `network_access`), `danger-full-access`, `external-sandbox`; `.git`/`.codex` stay read-only under a writable root (:1122-1132). The model is told its mode in prose (`codex-rs/prompts/templates/permissions/sandbox_mode/workspace_write.md`, `.../approval_policy/on_request.md`).

User answers: `Approved | ApprovedForSession | ApprovedExecpolicyAmendment | Denied { rejection } | Abort | TimedOut` (`protocol.rs:4143-4178`). Loosening: `--sandbox`, `--approve-for-me`, `--dangerously-bypass-approvals-and-sandbox`, `--add-dir` (`codex-rs/utils/cli/src/shared_options.rs:38-75`); `.rules` files with `prefix_rule(pattern, decision = allow|prompt|forbidden, justification)` (`codex-rs/execpolicy/README.md`). The model can also ask for wider rights via `request_permissions` (`codex-rs/core/src/tools/handlers/request_permissions.rs:32`). Headless `codex exec` forces `AskForApproval::Never` (`codex-rs/exec/src/lib.rs:566-568`) and rejects every approval or question request (:2001-2036). Undo: `TurnDiffTracker` per turn (`turn.rs:410-412`), `ThreadRolledBack` event (`protocol.rs:1404`); general rollback not found.

## 5. Steps and events to the UI
Internal `EventMsg` has ~80 variants (`protocol.rs:1360-1557`): `AgentMessageContentDelta`, `ReasoningContentDelta`, `ExecCommandBegin/OutputDelta/End`, `PatchApplyBegin/End`, `McpToolCallBegin/End`, `ExecApprovalRequest`, `RequestUserInput`, `PlanUpdate`, `TokenCount`, `ContextCompacted`, `StreamError`, `TurnAborted`, `TurnComplete`, `ItemStarted/Completed`.

`codex exec --json` collapses these to eight line types (`codex-rs/exec/src/exec_events.rs:8-37`): `thread.started {thread_id}`, `turn.started {}`, `turn.completed {usage}`, `turn.failed {error}`, `item.started | item.updated | item.completed {item}`, `error {message}`. An item is `{id: "item_N", type, ...}` (:96-133):
- message: `{"type":"agent_message","text"}` (completed only, :338)
- step/command: `{"type":"command_execution","command","aggregated_output","exit_code","status":"in_progress|completed|failed|declined"}` (:151-166)
- tool: `{"type":"mcp_tool_call","server","tool","arguments","result":{content,structured_content},"error","status"}` (:284-294); `file_change {changes:[{path,kind}],status}` (:184-189)
- plan: `{"type":"todo_list","items":[{text,completed}]}` — started on first `PlanUpdate`, `item.updated` on change, completed at turn end (`codex-rs/exec/src/event_processor_with_jsonl_output.rs:506-586`)
- question: no exec shape — rejected (`lib.rs:2025-2036`). Interactive shape: `RequestUserInputEvent { call_id, turn_id, questions:[{id, header, question, options:[{label, description}], isOther, isSecret}], isBlocking }` (`codex-rs/protocol/src/request_user_input.rs:9-71`).

Text streams as deltas; the JSONL mode emits text only as a completed item. Stalls: 300 s idle → reconnect up to 5× (`model-provider-info/src/lib.rs:59-60`), `StreamError` events, `ModelRerouted` surfaced as an `error` item (`event_processor_with_jsonl_output.rs:487-500`), unfinished started items reconciled to completed at turn end (:363-378).

## 6. Model portability
Provider = `ModelProviderInfo { name, base_url, env_key, wire_api, http_headers, env_http_headers, query_params, request_max_retries, stream_max_retries, stream_idle_timeout_ms, requires_openai_auth, supports_websockets, auth, aws }` (`codex-rs/model-provider-info/src/lib.rs:130-185`). Built-ins: openai, amazon-bedrock, ollama, lmstudio; "Users are encouraged to add to `model_providers` in config.toml" (:627-660). `WireApi` has one variant, `Responses`; `"chat"` now fails to deserialize (:98-125) — portability means "any endpoint speaking the Responses API", over SSE or WebSocket (`codex-rs/core/src/client.rs:2105-2118`). Per-model facts come from the `/models` endpoint as `ModelInfo { slug, context_window, auto_compact_token_limit, truncation_policy, shell_type, apply_patch_tool_type, supported_reasoning_levels, model_messages, include_skills_usage_instructions }` (`openai_models.rs:404-464, :703-710`); loop, tools and prompts are shared, tool flavour and instructions are per model. Switch with `-m`, `--oss`, `--local-provider`, `--profile` (`shared_options.rs:21-36`); a mid-thread switch injects `model_switch_instructions` (`codex-rs/core/src/context/model_switch_instructions.rs`).

## 8. The feel: what the harness does so a normal model feels smarter than it is
- **Anticipating the next step:** `update_plan` ("At most one step can be in_progress", `plan_spec.rs:42-47`) becomes a live `todo_list` item (§5); `ModeKind::Plan` collaboration mode (`codex-rs/protocol/src/config_types.rs:674-684`).
- **Recalling unasked:** AGENTS.md walk (§3); memories as a developer message every session (`context/memory.rs`); world state re-sent only when a section changed (`turn.rs:504-506`, `codex-rs/core/src/context/world_state/mod.rs`); a `CurrentTimeReminder` fragment before sampling so the model knows the clock (`codex-rs/core/src/session/time_reminder.rs:156-197`).
- **Showing the work:** reasoning and command-output deltas; `send_message_to_user_async` — "returns immediately without ending the turn or waiting for a reply" (`codex-rs/core/src/tools/handlers/send_message_to_user_async.rs:46`).
- **Never dead-ending:** sandbox denial → one ask → retry (§4); errors break the turn, not the thread (`turn.rs:776-779`); auto-compact mid-turn instead of failing (:602-642); the model can call `get_context_remaining` and `new_context` ("Start a new context window. Does not clear ... environment state", `codex-rs/core/src/tools/handlers/new_context_window_spec.rs:6-11`); the compaction prompt is a hand-off note to "another LLM that will resume the task" (`codex-rs/prompts/templates/compact/prompt.md`, `summary_prefix.md`).
- **One good question:** the `request_user_input` schema forces "Prefer 1 and do not exceed 3" questions, "2-3 mutually exclusive choices", recommended first, header ≤12 chars, and the client adds "Other" (`codex-rs/core/src/tools/handlers/request_user_input_spec.rs:35, :48-50, :72, :116-118`).
- **Continuity and steering:** rollout resume/fork (§1); the user can type while it works and the text is drained between steps (`turn.rs:424-434`).

## 9. The one thing to copy outright
**Copy:** the `codex exec --json` item lifecycle — eight event types, typed items with `item.started / item.updated / item.completed` and a `status` field, decoupled from the ~80 internal events (`codex-rs/exec/src/exec_events.rs:8-133`, mapping in `codex-rs/exec/src/event_processor_with_jsonl_output.rs:142-318`). Corner's phone chat should render exactly that: message, step, tool call, todo list, error — plus one item Codex lacks in JSON, the question, taken from `request_user_input.rs:9-71`.

**Avoid:** the approval matrix — `AskForApproval × SandboxPolicy × Granular × execpolicy × Guardian × hooks` spans `orchestrator.rs` (556 lines), `approvals.rs` (880) and `sandboxing.rs` (544). Corner has no shell; its risky verbs are send and spend. Keep only the three answers `Approved / ApprovedForSession / Denied { rejection }` (`protocol.rs:4143-4178`). And never do what headless `exec` does — rejecting questions outright (`lib.rs:2025-2036`); on the phone the question is an item, not an error.
