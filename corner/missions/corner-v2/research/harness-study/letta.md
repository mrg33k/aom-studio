# Letta (letta-code) — structural brief

**Repo / source:** https://github.com/letta-ai/letta-code at 6e84e8a (2026-09-16); landing repo letta-ai/letta at 5bcdd17 · **Read on:** 2026-09-17 · **Reader:** Claude (corner:corner-v2 R82 harness-study subagent)
**One line:** A stateful agent harness (CLI, desktop, chat.letta.com, Slack/Telegram) whose agent keeps identity and memory in a git-backed markdown filesystem that is compiled into the system prompt every turn.
**Why it is in the study:** The memory architecture: what is always in context, what is only indexed, what is searched, and a background "reflection" agent that consolidates memory between turns.

## 1. The loop
- A turn is one provider stream. The model decides the next action by emitting tool calls; the harness never plans. `src/backend/dev/provider-turn-executor.ts` maps every tool call to an `approval_request_message` chunk and closes the stream with `stop_reason: requires_approval`; plain text closes with `end_turn`; provider `length` becomes `max_tokens_exceeded`.
- The client (TUI `src/cli/app/use-conversation-loop.ts`, listener `src/websocket/listener/turn.ts`) runs the tools serially, then sends results back as `messages[].type === "approval"` in the next request (`src/backend/dev/headless-turn-executor.ts`). "`requires_approval` is a continuation boundary, not a terminal turn" (`src/websocket/listener/AGENTS.md`).
- Heartbeats: no `request_heartbeat` parameter survives; it is only stripped from display (`src/cli/helpers/format-args-display.ts:236`). "Heartbeat" now means a cron self-invocation: "Do NOT commit to actions beyond the current session without creating a cron" (`src/agent/prompts/letta_local_memfs.md` §Working across time; `src/cron/scheduler.ts`). Cron turns carry an autonomous notice: "no user is watching this turn" (`src/cron/scheduled-task-prompt.ts`).
- Budgets: no step cap in the primary loop (not found); `max_turns` exists only for listener/subagent runs (`src/runtime-execution-settings.ts`, `src/agent/subagents/manager.ts:258`). Context: compaction runs before the request when tokens exceed window − 16,384 reserve (20% for small windows) and again after an overflow error (`provider-turn-executor.ts` `contextCompactionThreshold`; `src/backend/local/local-backend.ts` `compactForContextPressure`/`compactAfterContextOverflow`). Retries: 3 for API errors, 2 for empty responses (second with a nudge) (`src/cli/app/constants.ts`).
- Turn end on `end_turn`: append transcript delta → evaluate reflection triggers → run Stop hooks (exit 2 feeds stderr back and continues) → `turn_end` mod event (may return `{continue}`) → post-turn memory git sync (`use-conversation-loop.ts` ~1424–1580; `src/reminders/memory-git-sync.ts`).
- Within a session: history is per conversation (`conversations/<id>/messages.jsonl`, per `src/agent/prompts/recall_subagent_local.md`). Compaction (default sliding window keeping 30%) replaces evicted messages with a first-person summary ≤300 words with "Errors and fixes" and "Lookup hints" sections (`src/backend/local/compaction.ts`). Harness notices travel as `role: user` `<system-reminder>` messages, never system role (`AGENTS.md` §Runtime Validation).

## 2. Skills and tools
- Tools are client-side: schema `src/tools/schemas/*.json`, prose `src/tools/descriptions/*.md`, impl `src/tools/impl/*.ts`; contract `(args, opts) => {toolReturn, status}` (`src/tools/README.md`). Toolsets are per model family (Claude `Read/Edit/Bash`, Codex `apply_patch/exec_command`, Gemini `read_file_gemini`) chosen in `src/tools/toolset.ts`; permissions canonicalize names (`src/permissions/canonical.ts`).
- Agents are created with `include_base_tools: false, include_base_tool_rules: false` (`src/agent/create-agent-request.ts:176-177`) and persisted server tool rules are wiped for letta-code agents (`src/tools/toolset.ts` `clearPersistedClientToolRules`). Sequencing is not done with tool rules.
- Skills are procedures, found from four sources in priority order: project `.agents/skills`, agent MemFS `skills/`, `~/.letta/skills`, bundled (`src/agent/skills.ts` header). Only name and first description line enter the prompt (`<available_skills>`, `src/backend/local/system-prompt-compilation.ts`); the body loads on demand via the `Skill` tool, "a BLOCKING REQUIREMENT: invoke ... BEFORE generating any other response" (`src/tools/descriptions/Skill.md`). MCP via `src/mcp-client.ts`; mods in `~/.letta/mods` register tools, commands and providers (`AGENTS.md` §Extension & Mod System).

## 3. Memory
Three tiers, named in the system prompt (`src/agent/prompts/letta_local_memfs.md` §Context Architecture; `letta_no_memfs.md` §Context architecture):

1. **Recall** — the immutable message history of every conversation, written by the harness, never loaded, only searched: `letta messages search` is full-text over JSONL transcripts (`src/backend/local/transcript-search.ts`), driven by a read-only `recall` subagent using "needle + expand" and date bounds (`src/agent/prompts/recall_subagent_local.md`). `<memory_metadata>` in the prompt states how many messages are in recall and when the prompt was last recompiled (`system-prompt-compilation.ts` `compileMemoryMetadata`).
2. **Core memory (memory blocks)** — always in context. Markdown files with `name`/`description` frontmatter in a git repo at `~/.letta/agents/<id>/memory/` (`src/agent/memory-filesystem.ts`). v1: `system/*.md` are core; v2: root `*.md` are core, root `MEMORY.md` is a frontmatter-free index, and a child directory is memory only if it has its own `MEMORY.md` (`src/agent/memory-format.ts`; `src/tools/descriptions/MemoryV2.md`). Defaults are `persona` ("ready to be shaped") and `human` ("I haven't gotten to know this person yet") (`src/agent/prompts/persona.mdx`, `human.mdx`; `src/agent/memory.ts`).
3. **External (archival) memory** — other markdown, skills, images in the same repo; only path and description are in context ("progressive disclosure", `letta_no_memfs.md`); the agent reads them with file tools.

**Compilation.** `compileLocalSystemPrompt` reads the committed HEAD (`git ls-tree`/`git show`), renders `<self>` (persona), `<memory>` with `<projection>` path, description and value per block, plus an `<external_projection>` tree of deferred paths, substituted into `{CORE_MEMORY}` (`src/backend/local/system-prompt-compilation.ts`).

**Who edits, when.**
- The agent in-turn with the `memory` tool (`str_replace|insert|delete|rename|update_description|create`, required `reason`): validates frontmatter, rejects no-op edits, auto-commits with the agent as git author, emits `memory_updated` (`src/tools/impl/memory.ts`; `descriptions/Memory.md`). Or raw edits plus `git commit`; a pre-commit hook enforces frontmatter and `read_only` (`src/agent/memory-git-hooks.ts`). A post-turn reminder nags "MEMORY COMMIT NEEDED" if dirty (`src/reminders/memory-git-sync.ts`).
- Edits are not live: "Editing memory does NOT change your behavior in the current turn" (`letta_local_memfs.md`). `local-backend.ts:936-975` recompiles when `memfsRevision` changes and, for models that accept it, injects a `<memory_update>` block mid-conversation ("this newer memory context wins", `local-backend.ts:236-246`).
- Corrections: frustration phrases ("I already told you that") are named as memory-write triggers, and "why did you forget?" must be answered as a context-engineering question (`letta_local_memfs.md` §Reacting to human feedback). `/remember` injects `src/agent/prompts/remember.md` (identify → pick block → confirm). The reflection prompt: "fix the stale entry at the source. Do not append the new version alongside the old"; retired content goes to a dated entry in root `ARCHIVE.md`.
- **Sleep-time consolidation ("dreaming").** A `reflection` subagent (`src/agent/subagents/builtin/reflection-v2.md`; Bash+Edit only, `--no-skills`, no base tools, sandboxed to the memory dir per `manager.ts`, `sandbox.ts`) launches after a turn when a trigger fires: default `compaction-event`, or every N completed assistant steps (default 25) (`src/cli/helpers/memory-reminder.ts`, `post-turn-reflection.ts`). It gets the transcript delta at `$TRANSCRIPT_PATH` plus the memory tree and core files inline, and runs five phases: Investigate → Extract (mistakes and corrections first, then preferences, facts, contradictions, reusable procedures; filters "lasting or ephemeral?", "already captured?", "generalizable?", relative dates to absolute) → Update → Review → Commit with `Parent-Agent-ID` trailer. It works in a harness-owned git worktree; outcomes `merged | no_changes | dirty_uncommitted | merge_conflict | parent_dirty`; only `merged` recompiles the prompt, and the transcript counts as consumed only on `merged|no_changes` (`src/agent/memory-worktree.ts:231-247`; `AGENTS.md` §Reflection Worktree). Merge mode `auto|explicit` ("agent reviews before applying", `src/cli/app/reflection.ts`).
- Journal or ledger: no per-day journal structure found. Closest: compaction summaries, the memory repo's `git log` ("it was your past self that constructed them"), and a usage ledger `~/.letta/sessions.jsonl` (`src/agent/session-history.ts`).
- Across machines: memory belongs to the agent and travels by git remote (`/memory-repository`, `src/agent/memory-git.ts`); environment skills stay with the machine.

## 4. Order of operations and approvals
- Turn setup order (listener `turn-setup.ts`, interactive parity): one-shot reminders in catalog order — session context, conversation bootstrap (5 recent + 5 relevant prior conversations, RRF-thresholded), agent info ("last run ... 3 days ago", memory dir), secrets, MCP, permission mode; all re-armed after compaction (`src/reminders/catalog.ts`, `state.ts` `markPostCompactionContextRemindersPending`; `src/cli/helpers/conversation-bootstrap.ts`, `agent-info.ts`).
- Tool rules are not used for sequencing (§2). Ordering lives in prompt rules: "modify your memory blocks first — never act in a way that conflicts with your current identity"; invoke Skill before answering; create a cron before promising future work; the reflection agent's fixed phase order.
- Approval evaluation order (`src/permissions/checker.ts:138-155`): 0 cross-agent memory guard (unbypassable) → 1 settings deny → 2 CLI `--disallowedTools` → 3 alwaysAsk rules → 4 permission mode → 5 CLI allowedTools → 6 Read/Glob/Grep inside cwd → 7 session allow → 8 settings allow → 9 settings ask → 10 tool default. Modes `unrestricted|standard|acceptEdits|strict`; the default is `unrestricted` (`src/permissions/mode.ts`). Memory tools count as edits under `acceptEdits`. Rules persist at `project|local|user` scope (`types.ts`).
- Hooks: `PreToolUse` and `UserPromptSubmit` can block (exit 2), `PermissionRequest` can allow or deny, `Stop` can block and force continuation; command or prompt hooks (`src/hooks/types.ts`).
- Undo: memory is git (revert, `git log`); reflection lands via merge commit and "NEVER semantically resolves conflicts" (`AGENTS.md`). Interrupt: ESC eager-cancels and injects `interrupt_recovery_alert.txt`; approval timeouts get a keep-alive `approval_recovery_alert.txt`. Subagents run `--permission-mode unrestricted` with inherited allowlists (`manager.ts`).

## 5. Steps and events to the UI
- Stream chunks (`provider-turn-executor.ts`): `reasoning_message` (thinking delta), `assistant_message` (text delta, `otid` groups contiguous segments), `approval_request_message {tool_call_id, name, arguments}`, `usage_statistics` (prompt, completion, context and cache tokens), `stop_reason`, `error_message {message, detail, error_type, retryable}`. UI-only state chunks are tagged with a symbol (`src/backend/local/local-stream-chunks.ts`).
- Listener turn state machine `idle|command|active|cancelling` with a lease per turn and exactly-once finalize (`src/websocket/listener/AGENTS.md`); app-server protocol v2 has runtime scope, state snapshots and reconnect (`src/types/protocol_v2.ts`).
- TUI: one focused approval at a time via `ApprovalSwitch`; static vs live transcript items (`src/cli/AGENTS.md`); subagent lifecycle items `pending|running|completed|error`, kept 30 s after finish (`AGENTS.md` §Subagent Lifecycle). `memory_updated` refreshes the web memory viewer (`memory.ts` `emitMemoryUpdated`; `/palace`).
- Stalls: provider timeout 5 min default (`src/backend/local/local-provider-timeout.ts`); 409-busy backoff 10/20/40 s (`constants.ts`); reflection over 10 min or 100 steps files telemetry feedback (`src/telemetry/reflection-threshold-feedback.ts`).

## 6. Model portability
- The provider layer is `@earendil-works/pi-ai`, which owns payload conversion, capability enforcement, the model catalog and env keys; the harness seam is `toPiMessage` in `src/backend/dev/pi-stream-adapter.ts` and the registry in `pi-provider-registry.ts` (Anthropic, OpenAI, Codex OAuth, Bedrock, Gemini, OpenRouter, Ollama, LM Studio, llama.cpp, Z.ai, MiniMax, Moonshot, Kimi; mods add more). `AGENTS.md` §pi-ai Ownership Boundary forbids provider fixups inside the harness.
- Identical across models: system prompt files, memory compilation, loop, permissions. Per model: toolset family, thinking-level mapping (`pi-model-factory.ts`), token accounting (`AGENTS.md` "Token counting differs by provider"), mid-conversation system messages only where supported (`local-backend.ts` `supportsMidConversationSystemMessages`), compaction model fallback for `claude-fable-5` (`compaction.ts`). Reflection uses `letta/auto-memory` on cloud, the parent's model locally (`subagent-model.ts:234-247`).
- Switching: `/connect` keys, `/model` per conversation; compaction follows the conversation's model (`local-backend.ts:643-649`). The identity line: "the model is the engine; *you* are the tokens" (`letta_local_memfs.md`).

## 7. How they know it is good
- Near-verbatim Claude Code, Codex and Gemini prompts are kept as `/system source-*` for benchmarking (`src/agent/prompts/README.md`). `scripts/latency-benchmark.ts` times fresh-agent vs resume scenarios. `/doctor` (`src/skills/builtin/context-doctor/SKILL.md`) audits memory structure and investigates incidents from transcripts; a token estimator warns when the prompt grows (`src/agent/system-prompt-size.ts`). Reflection telemetry with threshold alerts; `sessions.jsonl` usage ledger; a memory-citation mod makes the agent cite which memory files it actually read (`docs/examples/mods/memory-citations.ts`). Watchers diff competitor harness releases every 2 h (`scripts/claude-watch`). No memory-quality eval suite found in the repo; research is cited (MemGPT arXiv:2310.08560, sleep-time compute arXiv:2504.13171 in `CITATION.cff`, `README.md`).

## 8. The feel: what the harness does so a normal model feels smarter than it is
- Recalling unasked: first-turn bootstrap lists recent and relevant prior conversations (`conversation-bootstrap.ts`); "Jogging your memory": an unknown name must trigger recall and MemFS grep before "I don't know" (`letta_local_memfs.md`).
- Continuity: agent-info reminder with "last run N days ago"; `<memory_metadata>` message count; persona and human blocks recompiled every turn; memory follows the agent across machines; an onboarding block that deletes itself when done (`src/agent/prompts/onboarding_local.mdx`).
- Learning from friction: frustration phrases are write triggers; reflection ranks "mistakes and corrections" first; identity edits must be incremental to "avoid complete loss of self".
- Anticipating: "You MUST be proactive in arranging the appropriate future invocation" — crons and monitors (`letta_local_memfs.md`); cron turns are told to deliver via channels or memory since nobody is watching (`scheduled-task-prompt.ts`).
- Showing the work: reasoning stream, one focused approval, subagent panel, background reflection visible as lifecycle items.
- Never dead-ending: Stop hooks can bounce an incomplete answer; "A successful tool call does not replace an answer the user requested" (`letta_local_memfs.md` §Following user requests); interrupt and approval recovery alerts; empty-response retry with a nudge.
- One good question: `AskUserQuestion` puts the recommended option first and always offers "Other" (`src/tools/descriptions/AskUserQuestion.md`); the reflection agent cannot ask and must document assumptions instead.

## 9. The one thing to copy outright
**Copy:** the three-tier memory contract compiled from committed files, `src/backend/local/system-prompt-compilation.ts` with the tier rule in `src/tools/descriptions/MemoryV2.md`: short core files (always in context, each with a `description`), deferred files (only path and description in context, indexed by `MEMORY.md`), and immutable recall that is searched, never loaded. For Corner: standing facts per project are core files; the day journal is deferred dated files under an index; the ledger of what was done is the message log plus the memory repo's `git log`. Pair it with the `memory` tool contract (required `reason`, no-op rejection, one commit per edit) and the post-turn reflection with "mistakes first" extraction (`reflection-v2.md`).

**Avoid:** memory edits that only take effect on the next recompile. Letta needed the `<memory_update>` injection (`local-backend.ts:236-246`) and the "you are writing for your future self" caveat to cover the gap; Corner should apply an edit to the pack before the next call in the same session. Also avoid `unrestricted` as the default permission mode (`src/permissions/mode.ts`) for a phone user whose agent can send email.
